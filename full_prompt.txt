/goal # MASTER IMPLEMENTATION PROMPT
## Replace Execution Journal with a Premium Daily Work & Burndown Intelligence Dashboard

### ROLE & OBJECTIVE

Act as a Principal Frontend Architect, Senior Full-Stack Engineer, Enterprise UI/UX Designer, Data Visualization Specialist, Azure DevOps Integration Expert, and QA Automation Engineer.

Your mission is to completely redesign and replace the existing **📜 Execution Journal** section with a powerful, visually stunning, interactive, and production-ready **Daily Work & Burndown Intelligence Dashboard**.

Use the provided Angular Daily Burndown HTML as a **functional reference**, not as a design to copy.

The new implementation must be more elegant, intuitive, intelligent, useful, responsive, and visually refined than both the existing Execution Journal and the provided reference.

**Do not simply rename the existing section or change its styling. Reimagine the entire experience while preserving all existing functionality and valuable execution records.**

---

## 1. EXISTING APPLICATION ANALYSIS

Before implementing anything, comprehensively inspect the existing application.

Identify:

- The purpose and current functionality of Execution Journal.
- Existing execution history, event logs, and automation records.
- Azure DevOps API integrations and available data.
- User management and multi-user workflows.
- Task creation, activation, updating, and closing workflows.
- Work item relationships and statuses.
- Existing dashboards, charts, filters, and reporting components.
- Backend services, data structures, and state management.
- UI components, design tokens, styling conventions, and reusable utilities.
- Loading, error, caching, and synchronization mechanisms.

Determine which features should be retained, enhanced, relocated, or replaced.

Do not delete useful existing functionality.

**Important:** The new dashboard must preserve access to technical execution logs and automation audit history. Relocate them into a dedicated Activity & Audit view instead of discarding them.

---

## 2. NEW DASHBOARD IDENTITY

Replace:

**📜 Execution Journal**

With:

# Work Intelligence

Subtitle:

**Track daily contributions, monitor team workloads, analyze task progress, and understand delivery performance in one unified workspace.**

The dashboard should feel like a sophisticated modern SaaS analytics platform.

### Design Direction

Create a premium enterprise interface inspired by the quality and usability of modern productivity and analytics applications.

Visual characteristics:

- Clean, spacious layouts.
- Beautiful typography and strong visual hierarchy.
- Carefully balanced spacing.
- Professional, restrained color palettes.
- Subtle gradients where appropriate.
- Refined borders and shadows.
- High-quality custom charts.
- Smooth micro-interactions.
- Elegant hover and focus states.
- Modern dropdowns, date selectors, and filters.
- Compact but readable data tables.
- Consistent iconography.
- Carefully designed loading skeletons.
- Responsive cards and panels.
- Seamless dark and light themes.
- Accessible colors and controls.

Avoid:

- Outdated enterprise table styling.
- Excessive gradients.
- Overcrowded interfaces.
- Unnecessary animations.
- Excessive emojis.
- Unreadable small text.
- Oversized cards with little information.
- Random color usage.
- Horizontally overflowing page layouts.
- Fake analytics or decorative nonfunctional controls.

The result should be visually impressive while remaining practical for everyday professional use.

---

## 3. DASHBOARD INFORMATION ARCHITECTURE

Build the experience around the following integrated views.

### A. Overview
The central dashboard showing key metrics, charts, team progress, and important actions.

### B. Daily Burndown
A powerful interactive matrix inspired by the supplied reference.

### C. My Work
A personalized view of the selected user's daily tasks, effort, and completion history.

### D. Team Insights
Multi-user productivity, allocation, availability, and workload analysis.

### E. Task Explorer
A detailed, searchable interface for viewing Azure DevOps work items.

### F. Activity & Audit
A redesigned replacement for the historical Execution Journal with detailed automation events, API operation outcomes, and traceable execution records.

Use tabs, segmented navigation, or context-appropriate routing to keep the experience organized without overwhelming the user.

---

## 4. EXECUTIVE OVERVIEW

Design a beautiful overview containing interactive KPI cards.

Possible metrics include:

**Total Tasks**
Number of Azure DevOps tasks matching the selected filters.

**Completed Tasks**
Number of tasks completed during the selected period.

**Active Tasks**
Number of currently active work items.

**Planned Tasks**
Number of future or scheduled tasks.

**Total Completed Work**
Sum of recorded completed work hours.

**Remaining Work**
Outstanding effort based on supported Azure DevOps fields.

**Completion Rate**
Percentage of qualifying tasks completed.

**Team Members**
Number of unique team members matching the current selection.

Additional useful indicators:

- Tasks requiring attention.
- Overdue work items.
- Missing task assignments.
- Users without expected daily tasks.
- Planned versus completed effort.
- Task creation and closure trends.

Each KPI card should include relevant context, such as comparisons with the previous period, when the necessary data is available.

Clicking a KPI should filter or navigate to the corresponding task records.

Do not generate fabricated percentages, trends, or comparisons.

---

## 5. PREMIUM DAILY BURNDOWN MATRIX

This is one of the most important features.

Use the supplied Angular Daily Burndown matrix as a functional reference, but completely rethink its visual presentation.

### Matrix Structure

| Team Member | Total Work | Task Count | 01 Thu | 02 Fri | 03 Sat | ... |
|---|---|---|---|---|---|---|
| Member A | 40h | 4 | 8h | Holiday | WO | ... |
| Member B | 32h | 4 | 8h | Holiday | WO | ... |

The matrix must dynamically generate all dates for the selected month and year.

### Essential Features

- Month and year selection.
- Team/POD selection.
- Multi-user selection.
- Daily effort visualization.
- Total completed work.
- Total task count.
- Weekend and holiday differentiation.
- Current-day highlighting.
- Sticky headers.
- Sticky team-member columns.
- Smooth horizontal and vertical scrolling.
- Fullscreen or expanded table mode.
- Sorting by name, hours, task count, and completion.
- Search across users.
- Export to Excel and CSV.
- Responsive layout.
- Loading, empty, error, and partial-data states.

### Intelligent Cell Design

Instead of a plain rectangular cell containing a number, implement carefully designed status cells.

Suggested meaning:

- Green: completed work.
- Blue: active work.
- Amber: partial or pending work.
- Red: confirmed overdue or problematic work.
- Muted grey: weekends or nonworking days.
- Distinct neutral treatment: holidays.
- Empty or unavailable indicator: missing data.

Do not use the same colors for unrelated meanings.

Never equate missing data with zero recorded effort.

Use explicit labels, tooltips, patterns, and accessible descriptions.

### Interactive Day Details

Clicking a date cell should open an elegant side panel or contextual detail view containing:

- Selected team member.
- Selected date.
- Associated Azure DevOps tasks.
- Work item IDs and titles.
- Current task states.
- Original estimates.
- Completed work.
- Remaining work.
- Task creation and completion timestamps.
- Associated parent work items.
- Related links and available evidence.
- Automation execution events, where applicable.

Include a direct link to the relevant Azure DevOps work item.

All information must originate from actual application records or authorized integrations.

## 6. ADVANCED DATA VISUALIZATIONS

Introduce a cohesive set of high-quality visualizations.

### Daily Effort Trend

Create an interactive line or area chart showing completed work by day.

Support individual users and aggregated team views.

### Planned vs Completed Work

Create a clear comparison chart showing recorded planned and completed effort.

Make units explicit and do not mix hours with story points.

### Task Status Distribution

Display actual work item statuses using a donut chart or another appropriate visualization.

### Workload Distribution

Visualize how work is distributed across selected team members.

Highlight meaningful imbalances only when there is sufficient data and a defined capacity baseline.

### Burndown Trend

Create a proper burndown chart where the required scope and historical data exist.

Distinguish:

- Ideal remaining work.
- Actual remaining work.
- Scope changes.
- Forecasts, if supported by the data.

Do not incorrectly label cumulative completed hours as remaining-work burndown.

### Activity Heatmap

Provide a modern calendar heatmap representing daily work activity.

Support day-level drilldowns.

Tooltips must display meaningful, precise information.

Charts must share the active dashboard filters and update consistently.

- Month.
- Year.
- Team/POD.
- User or multiple users.
- Work item status.

- View work across all configured users.

- Existing multi-user task automation.

### Data Integrity Requirements

- No dummy tasks.
- No fake users.
- No fabricated hours.
- No invented KPI values.
- No hardcoded production statistics.
- No simulated API success.
- No misleading real-time indicators.

**Live** — freshly retrieved and verified data.

**Cached** — previously retrieved data with a timestamp.

**Partial** — incomplete results.

**Unavailable** — data could not be retrieved.

Use a visible Last Synced timestamp and a functional refresh action.

- Incremental data loading.
- Background refresh while the application is open.
- Chart rendering optimization.

- Enforce authorization on backend operations.
- Handle API throttling.
- Protect against duplicate operations.
- Use proper error boundaries.
- Avoid storing sensitive data unnecessarily.

- Token expiration.
- Invalid credentials.
- Network disconnection.
- Incomplete API responses.
- API throttling.
- Unexpected work item states.
- Missing user assignments.
- Partial synchronization.
- Empty result sets.
- Concurrent changes.

Execute the work in this order:

**Phase 1 — Discover**

Audit the existing Execution Journal, data sources, components, and integration capabilities.

**Phase 2 — Design**

Define the information architecture, visual direction, component hierarchy, and interaction patterns.

**Phase 3 — Build the Foundation**

Implement the new page structure, navigation, responsive layout, design tokens, and shared components.

**Phase 4 — Integrate Real Data**

Connect to supported APIs, normalize actual data, and implement reliable loading and error handling.

**Phase 5 — Build Analytics**

Implement KPIs, burndown matrix, charts, heatmap, and drilldowns.

**Phase 6 — Restore Operational History**

Integrate existing Execution Journal records into Activity & Audit.

**Phase 7 — Refine**

Improve spacing, animations, interactions, readability, responsiveness, and accessibility.

**Phase 8 — Verify**

Run functional, integration, data-accuracy, security, and regression tests.

**Phase 9 — Final Review**

Inspect the complete experience, correct verified problems, and document outstanding integration limitations.

Do not remove an existing workflow until its replacement has been validated.
