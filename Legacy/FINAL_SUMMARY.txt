STREAMING RESPONSE FORMAT
═══════════════════════════════════════════════════════════════════════════════

Server sends Server-Sent Events in this format:

data: {"type": "started", "dateRange": {...}, "message": "..."}
data: {"type": "progress", "message": "...", "progress": 25}
data: {"type": "progress", "message": "...", "progress": 50}
data: {"type": "progress", "message": "...", "progress": 75}
data: {"type": "complete", "data": {...}, "progress": 100}

Or on error:
data: {"type": "error", "error": "Error message"}

KNOWN LIMITATIONS & NOTES
═══════════════════════════════════════════════════════════════════════════════

⚠️ EventSource Protocol:
   - Only supports GET requests (perfect for our use case)
   - Auto-reconnects if server closes (good!)
   - One connection per endpoint (normal)
   - Headers cannot be custom (uses query params)

⚠️ Data Processing:
   - Server still processes all data internally
   - Progress updates show processing milestones
   - Very large datasets (10k+ items) may take longer
   - This is normal and expected

SUPPORT & TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

If streaming doesn't work:

1. "No progress bar showing?"
   → Check server running: npm start
   → Check console for errors: F12
   → Check .env has credentials

2. "Stream connection lost?"
   → Server may have crashed
   → Check network connection
   → Restart server: npm start

3. "Progress stuck at X%?"
   → Normal - Azure DevOps API is processing
   → Larger datasets take longer
   → Be patient, it will complete

4. "No data after 100%?"
   → Check browser console for errors
   → Check network tab response
   → Clear cache: Ctrl+Shift+Delete
